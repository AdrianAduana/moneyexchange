Reflection: git add vs. git commit
Think of preparing code changes like packing a moving box to ship to storage:

git add (The Packing Table): This is like picking items up from your desk and placing them neatly onto the packing table. You are telling Git, "Hey, look at these specific files; I want to include them in my next batch." It gathers your changes into a staging area, but nothing is locked in yet.

git commit (Sealing & Labeling the Box): This is like taping up the box, writing a clear label on the outside describing what is inside (e.g., "Added currency conversion calculator"), and locking it into your permanent storage logbook. It takes a permanent snapshot of your staged files and saves them securely into your project's history.
